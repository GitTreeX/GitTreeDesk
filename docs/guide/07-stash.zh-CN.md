# 07 · Stash

> 状态：🚧 计划中 · 范围：v1 · 工程参考：[`../spec.md`](../spec.md)

## 创建 stash

入口：Source Control 视图工具栏（按仓库）、仓库右键菜单，或命令面板。

| 选项 | 默认 | 含义 |
|---|---|---|
| 消息 | 空 | 显示在 stash 列表中的描述（如 "wip before rebase"）。 |
| 包含未跟踪文件 | 关 | 新文件也一并 stash。 |
| 保留 index | 关 | 已暂存内容在 stash 后仍保持暂存状态留在工作树。 |
| 路径子集 | — | 先选中文件/文件夹，再"Stash 所选路径"——只 stash 这些改动。 |

创建后，被 stash 的路径在工作树中恢复干净，仓库徽标同步更新。

## Stash 列表

- 位于仓库详情面板；同时以 `⚑n` 徽标概要显示（第 01 页）。
- 每条记录：消息、来源分支、相对时间与文件数。展开可列文件；点击文件打开该 stash 中该文件的 diff。
- Stash 是**仓库级**的（该仓库所有 worktree 共享），apply 时作用于当前 worktree 的工作树。

| 操作 | 行为 |
|---|---|
| **Apply** | 应用但保留记录。 |
| **Pop** | 应用成功后移除记录；若应用时产生冲突，记录会**保留**并进入冲突流程（第 06 页）——绝不静默丢失。 |
| **Drop** | 删除记录；会先创建 backup ref（可撤销，第 06 页）。 |
| **Show** | 在编辑区打开该 stash 的完整 diff。 |

## 与其他操作的协作

- Checkout、pull、rebase 在工作树脏时可执行"**自动 stash**"。临时 stash 使用生成的消息（`autostash: <操作名>`），操作完成后**自动恢复**。
- 若自动恢复发生冲突，stash 记录会被保留，并通过横幅提示稍后处理——自动流程绝不丢弃你的改动。
- 有进行中的操作（merge/rebase……）时禁止 stash；弹窗会先提供 Continue/Abort。

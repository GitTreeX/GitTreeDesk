# 06 · 合并、变基与冲突

> 状态：✅ 已实现 · 范围：v1 · 工程参考：[`../spec.md`](../spec.md)

## 合并（Merge）

- 入口：在**分支选择器**里右键某分支 → **"合并到当前分支"**。提交图侧的合并入口来自分支/ref 行自身的菜单（第 09 页）。
- 选项：`--no-ff`（生成合并提交）、`--squash`（压缩后的变更进入暂存区、不提交）、`--ff-only`。
- 结果：汇总 toast（快进 / 生成合并提交 / 有冲突）；出现冲突时展示操作横幅（见下文）。

## 变基（Rebase）

- **把当前分支变基到…**——任选 ref；脏工作树会先自动 stash（完成后恢复）。
- **交互式 rebase**——入口在提交图（右键某提交 → "自此交互式 rebase"）或分支选择器：
  - 列表编辑器逐行显示将要重放的提交。行操作：**pick / reword / edit / squash / fixup / drop**（行内按钮）。
  - v1 用上移 / 下移调整顺序；拖拽排序为 [Later]。
  - 变基过程中，操作横幅提供 **Continue / Skip / Abort**；停在 `edit` 行相当于暂停——amend 或执行命令后 Continue。
- 两种 rebase 都在后台执行、不阻塞窗口；整段 Git 输出进入 Output 面板，提交图在变基结束或停下时刷新。

## Cherry-pick 与 Revert

- **Cherry-pick**——从提交图或提交详情面板逐个选择提交；可选 `--no-commit`（变更进入暂存区，先不提交）。区间（`A..B`）为 [Later]。
- **Revert**——入口与选项同上；revert 合并提交需选择主线（对话框会解释哪个 parent 是哪个）。
- 冲突走同一套横幅流程。

## Reset

右键某提交 → **"把当前分支重置到此处"**：

| 模式 | 行为 |
|---|---|
| **Soft** | 仅移动分支指针；index 与工作树不动（改动保持已暂存）。 |
| **Mixed** | 移动分支指针；重置 index；改动留在工作树（未暂存）。 |
| **Hard** | 全部重置——**工作树改动会丢失**。需确认；对话框会点名将被丢弃的提交，且会**先创建 backup ref**。 |

## 冲突处理

操作因冲突停下时（merge、rebase、cherry-pick、revert）：

1. 仓库分节顶部与提交图中出现**操作横幅**：**Continue / Skip / Abort**，以及未解决文件数的实时计数。
2. **Conflicts 组**（第 03 页）列出冲突文件。对每个文件：
   - **Ours / Theirs / Both** 解决操作，
   - **在编辑器中打开**（带语法高亮的冲突标记），
   - **在外部合并工具中打开**——命令可在设置中配置（如 Beyond Compare、WinMerge、KDiff3）。
3. 已解决的文件可标记（"标记为已解决"，或暂存时自动标记）。
4. **Continue 前会校验**：若仍有未解决文件，弹窗列出清单，而不是让 Git 中途失败。
5. **Abort** 精确恢复操作前状态；**Skip**（rebase/cherry-pick）跳过当前提交。

**stash apply/pop** 冲突是例外：它不会开启一个操作，因此没有横幅。stash 记录保留，冲突文件带着标记留在工作树，并有一条提示说明发生了什么（第 07 页）。

## 编辑器内的冲突处理

内置编辑器显示标准冲突标记（`<<<<<<<`、`=======`、`>>>>>>>`），边栏提供 *采纳 ours / 采纳 theirs / 全部采纳* 操作。完整的三方合并编辑器为 [Later]。

## 安全网

- 每个破坏性操作之前——reset `--hard`、rebase（含交互式）、历史改写、stash drop、删除分支、强制删除 worktree——GitTreeDesk 都会在 `refs/gitreedesk/backup/…` 下创建**backup ref**，指向即将被替换的状态。backup ref 不出现在常规分支/tag 列表中。
- 操作完成后，toast 提供 **Undo**（恢复 backup ref）。之后仍可从仓库右键菜单 → **"从备份恢复…"** 找回，列表显示每次备份的操作、时间与目标 ref。
- 备份/撤销历史同时记录在该仓库的操作日志中（Output 面板）。

## 被拦截的操作

有进行中的操作时，GitTreeDesk 会拦截与之冲突的操作（例如 merge 中发起 rebase），弹窗解释原因并给出合法的下一步动作（先 continue / 先 abort）。
